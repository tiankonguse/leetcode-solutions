分析：

这道题题目就很复杂，若干条地铁线路，每个线路有若干个站点。  
对于每个站点，换乘需要先到站厅，所以每个线路的每个站点到站厅都有一个固定的走路时间。  
另外，每个站点到出口也有一个固定的走路时间。  


题目是要求从一个地铁站出口到达另外一个地铁站出口的最少走路时间。  
首先，从两个地铁站出口走到自己的站厅的时间是固定的。  
剩下的就是这两个站点分别选择一条线路，目标是线路之间换乘走路时间最少。  


第一张思路是线路和地铁站都当做一个点，构图，求全源最短路。  
然后 Floyd 求全源最短路  
复杂度：`O((n+m)^3)`
得分： 40 分
参考代码: subway-v1-40-n-m-matrix.cpp


性质 A 说每个线路最多 2 个地铁站，所以构图时可以只使用地铁站，这样图就少了 n 个点。  
然后 Floyd 求全源最短路  
复杂度：`O(m^3)`
得分： 44 分
参考代码： subway-v2-44-property-A.cpp


Floyd 计算全源最短路复杂度有点高。  
所以可以尝试构图邻接表，求 m 次通过 Dijkstra 求最短路。  
复杂度： `O(m * E * log(E))`
得分：48 分
参考代码： subway-v3-48-table.cpp  


其实只需要对询问的点求最短路，故可以使用 hash 记录询问的点。  
得分：48 分
subway-v4-48-table-query.cpp  


Dijkstra 求最短路时也可以使用性质A构图，少 n 个点。  
得分：48 分
subway-v5-48-table-property-A.cpp  


性质B：所有站点到站厅的时间一样。  
这种情况，就不需要 Dijkstra 求最短路，直接 BFS 即可。  
复杂度： `O(m * E)`
得分：48 分
subway-v6-48-property-B.cpp


第 20~21 组测试数据，n 不超过 2。  
n 等于 1 时，答案固定，直接上地铁与下地铁，直接计算答案即可。  
n 等于 2 时，最多换乘一次，且两条线的最小换乘时间是固定的，分情况讨论即可。  
复杂度：`O(1)`  
得分：56 分  
subway-v7-56-t20-21.cpp  


可以发现，做了很多优化，很难提升分数了。  
这是由于 站点 m 很大，构图至少有 m 个点，最短路至少是 `n^2`，必然超时。  


数据上还有两个数字是突破口。  
第一个是线路，最多只有 500 条。  
第二个是经过地铁站的线路，最多 20 条。


这两个数据就是这道题正确解法的钥匙。  


首先，可以预处理出所有线路之间走的最少时间。  
经过一个地铁站的线路最多 d 条，这些线路之间可以构造连边。  
复杂度：`O(m*d^2)`  


构图之后，再使用求线路的全源最短路。  
复杂度：`O(n^3)`  


询问时，只需要枚举出发地铁站的线路与到达地铁站的线路，求最小值，即可得到最少走路时间。  
复杂度：`O(q * d^2)`  


综合复杂度：`O(m * d^2 + n^3 + q * d^2)`
得分：100 分
代码：subway-v7-100.cpp
